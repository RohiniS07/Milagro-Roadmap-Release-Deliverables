Darshan's Report Verification Workstreams

D
Darshan is responsible for all backend scripting and Playwright test cases for SmartPOS report verification. For every transaction completed in Track B, Darshan validates that the reports generated — Revenue Summary, Sales Revenue, and Payment Summary — are consistent between Open Day and Closed Day states across 3 dedicated test locations. This track runs in parallel via API work while Tracks A & B execute.

CI / PR Strategy

How the CI pipeline works
When a PR is opened or updated against dev or prod, the build.yml workflow calculates affected rules. If SmartPOS E2E files are touched, it spins up hermetic Docker services, starts an Android emulator, and runs the Playwright suite authored by Darshan. Two tiers exist — a PR Smoke Suite (fast, every PR) and a Nightly Full Suite (comprehensive, pre-release).
